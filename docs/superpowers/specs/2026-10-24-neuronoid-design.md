# Neuronoid — дизайн

Дата: 2026-10-24
Статус: ждёт утверждения (вопросы ревьюера учтены)

## Зачем

Программа, которая **сама** учится играть в оригинальный DOS-Arkanoid (Taito, 1988),
запущенный в эмуляторе DOSBox, и в идеале проходит его. «Сама» — как человек:
агент видит только экран и нажимает клавиши. Это личный исследовательский проект
в духе DeepMind на Atari, но на DOS-классике. Важна честность подхода и
возможность увидеть результат своими глазами.

## Цели

1. Агент учится играть с нуля методом обучения с подкреплением (RL),
   используя **только пиксели экрана**.
2. **Награда тоже извлекается только из картинки:** счёт распознаётся с экрана
   (сравнение с образцами цифр фиксированного шрифта), жизни — по иконкам
   ракеток, «Game Over» и смена раунда — по виду экрана.
3. **Живое окно:** в любой момент обучения можно открыть окно и смотреть,
   как играет один из параллельных экземпляров.
4. **Режим показа:** обученный агент играет в окне на нормальной скорости игры,
   со звуком (если получится), с панелью «что думает агент» (выбранная клавиша,
   вероятности действий, счёт, раунд, сколько часов обучения). Плюс запись
   партии в видеофайл.
5. Пройти как можно больше раундов. Ступени успеха:
   - М1: агент стабильно отбивает мяч и набирает очки;
   - М2: проходит раунд 1;
   - М3: доходит до раунда 5;
   - мечта: проходит все 33 раунда (не гарантируется).

   **Как засчитываем (решение пользователя):** раунд N считается пройденным,
   только если агент дошёл до него в **новой игре с раунда 1**, с обычным
   запасом жизней и без продолжений. Savestates учебной программы — только
   тренировка, на зачёт не влияют. «Стабильно» для М1 и зачёт ступеней —
   по серии оценочных игр (например, ≥ 7 из 10), точный порог — за исполнителем.

   **Против заучивания (моё решение):** игра со savestate детерминирована, и
   агент мог бы выучить слепую последовательность нажатий. Поэтому в обучение и
   оценку добавляется случайность: случайное число пустых кадров на старте и
   «залипающие» действия (с малой вероятностью повторяется предыдущее).

## Не цели

- Не читаем память эмулятора — ни для решений, ни для награды, ни для
  определения конца игры. Это жёсткое правило проекта.
  **Единственное исключение (одобрено пользователем):** офлайн-инструменты
  проверки `ScreenReader` могут читать RAM, чтобы автоматически размечать
  тестовые кадры (счёт/жизни/раунд). Этот код живёт отдельно (`tools/`,
  `tests/`) и никогда не импортируется средой, обучением или показом.
- Не пишем свой RL-алгоритм с нуля: берём проверенную библиотеку.
- Не управляем отдельно запущенным обычным DOSBox — это возможный бонус
  после успеха (см. «Потом»).
- Не делаем веб-интерфейс, облако, распределённое обучение.

## Анти-цели (провал, даже если «работает»)

- Любая «подсказка» агенту из RAM эмулятора.
- Ручные правила вида «двигай ракетку под мяч» вместо обучения.
- Обучение, которое на этом ноутбуке требует недель до М1.

## Ограничения

- Железо (обучение — здесь, решение пользователя): ноутбук, Intel Core
  Ultra 7 255H (16 ядер), 32 ГБ ОЗУ, встроенная Intel Arc 140T (не NVIDIA),
  Windows 11. Есть также MacBook Pro 16" M4 — код должен оставаться
  кроссплатформенным (пути, ядро `.dll`/`.dylib`, устройство `cpu`/`xpu`/`mps`),
  чтобы обучение можно было перенести туда без переделок.
- Игра лежит в `games/arkanoid/` (в `.gitignore`).
- Python: в системе 3.14; для проекта — отдельное окружение на 3.12
  (совместимость ML-библиотек).
- Игра: лицензионная копия пользователя, DOS-версия под DOSBox. **Файлы игры
  не попадают в git** (`.gitignore`), путь к ним задаётся в конфиге.
- Ноутбук будет работать под полной нагрузкой часами: учитывать перегрев,
  предусмотреть ограничение числа экземпляров и сохранение/возобновление
  обучения.

## Подходы (рассмотренные)

| | Подход | Плюсы | Минусы |
|---|---|---|---|
| A | Обычный DOSBox в окнах + захват экрана + эмуляция нажатий Windows | просто, эмулятор не трогаем | почти реальное время, дорогой захват, окна конфликтуют за фокус, дни обучения |
| **B** | **Ядро DOSBox Pure (libretro) как библиотека внутри Python** | быстро (сколько тянет CPU), кадры прямо из памяти, независимые экземпляры, savestates | нужна прослойка-фронтенд; риск, что игра капризничает в DOSBox Pure |
| C | Доработать исходники DOSBox (C++) | полный контроль | сборка C++ под Windows, много работы ради того, что B даёт почти даром |

**Выбран B** (решение пользователя). Если этап 0 покажет, что DOSBox Pure не
работает, по порядку (моё решение): другое libretro-ядро DOS → DOSBox-X /
DOSBox Staging без окна → C → и только потом A (A противоречит анти-цели по
срокам, поэтому крайняя мера).

## Как устроено (решено)

```
 твой Arkanoid ──► DOSBox Pure (libretro .dll)
                        │  кадр (пиксели), звук
                        ▼
                 LibretroEmulator (ctypes-фронтенд)
                        │
                        ▼
                 ArkanoidEnv (Gymnasium)
                   ├─ obs: обрезка игрового поля, ч/б, уменьшение, стек кадров
                   ├─ ScreenReader: счёт / жизни / Game Over / раунд — с картинки
                   └─ reward из ScreenReader
                        │  ×10–12 процессов
                        ▼
                 PPO (Stable-Baselines3) ──► чекпоинты, TensorBoard
                        │
        ┌───────────────┴───────────────┐
   LiveViewer (окно, экземпляр №0)   DemoPlayer (реальная скорость,
                                     звук, панель агента, запись видео)
```

- **Эмулятор:** ядро `dosbox_pure_libretro.dll`, загружаемое из Python.
  Фронтенд — готовый пакет (например, `libretro.py`), если подойдёт, иначе
  свой минимальный на `ctypes`. Нужны: загрузка игры, `run()` одного кадра,
  получение кадра, подача ввода, сохранение/загрузка состояния, звук (для показа).
- **Управление:** клавиатура. Дискретные действия: `NOOP`, `LEFT`, `RIGHT`,
  `FIRE`, а также `LEFT+FIRE`, `RIGHT+FIRE`, если игра позволяет. Мышь не используем.
- **Наблюдение:** только пиксели игрового поля после предобработки;
  frame skip ~4, стек из 4 кадров.
- **Награда:** прирост распознанного счёта (масштабированный), штраф за потерю
  жизни, бонус за переход в новый раунд. Всё — из `ScreenReader`.
- **Эпизод:** начинается с savestate «раунд N, мяч на ракетке», кончается на
  Game Over (или на потере жизни — как вариант для ускорения обучения).
- **Параллельность:** 10–12 процессов с эмулятором (`SubprocVecEnv`), остальные
  ядра — на обучение. Нейросеть — небольшая CNN; считать на CPU, Intel Arc
  через PyTorch XPU — опционально, если даст выигрыш.
- **Учебная программа через savestates агента:** когда агент впервые доходит до
  нового раунда, состояние автоматически сохраняется; дальше часть экземпляров
  стартует с уже достигнутых раундов. Savestates делает только сам агент,
  ручных сохранений человека нет — так подход остаётся «чистым».
- **Живое окно:** отдельный лёгкий процесс/поток, показывающий кадры
  экземпляра №0; открывается и закрывается в любой момент без остановки обучения.
- **Режим показа:** загружает чекпоинт, гонит эмулятор в реальном времени
  (~70 Гц, как в DOS), выводит картинку в оригинальном виде, звук и панель
  агента, по флагу пишет MP4.
- **Стек:** Python 3.12, `uv` для окружения, Gymnasium, Stable-Baselines3,
  PyTorch, NumPy, OpenCV, pygame (окно и звук), TensorBoard.

## Этапы

0. **Проверка (spike):** осмотреть копию игры (издание, формат, число раундов,
   есть ли защита от копирования на старте — если есть вопрос из руководства,
   ответ подаётся автоматической последовательностью при подготовке). Запустить Arkanoid в DOSBox Pure из Python, получить
   кадр, нажать клавишу, сохранить/загрузить состояние, замерить кадры/с на
   один экземпляр без окна. Критерий «идём дальше»: игра работает и даёт
   ≥ 300 кадров/с на экземпляр. Иначе — разбор или откат на подход A.
1. **Среда:** `LibretroEmulator`, `ArkanoidEnv`, `ScreenReader` с тестами на
   записанных кадрах (счёт, жизни, Game Over, раунд распознаются верно).
2. **Живое окно.**
3. **Обучение:** PPO, параллельные экземпляры, чекпоинты, возобновление,
   TensorBoard. Цели М1 → М2.
4. **Режим показа** с панелью агента и записью видео.
5. **Учебная программа** по savestates, движение к М3 и дальше.

## Оставлено исполнителю

- Точные размеры обрезки и уменьшения кадра (мяч мелкий — не потерять его).
- Гиперпараметры PPO, масштаб наград, число экземпляров (с оглядкой на нагрев).
- Готовый libretro-фронтенд или свой на `ctypes`.
- Как именно проходить меню игры до первого savestate (автоматическая
  последовательность клавиш при подготовке — это не управление агентом).
- Формат конфигурации и логов.

## Потом (не в этом проекте)

- Обученный агент управляет отдельно запущенным обычным DOSBox через захват
  окна и эмуляцию клавиш.
