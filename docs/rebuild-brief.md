# Neuronoid: как пройти этот путь заново и чисто

Документ для повторения эксперимента с нуля: что строили, какие ловушки нашли и что сделать с первого дня.
Подробности по каждому решению — `docs/spike-report.md`, `docs/training-log.md`, планы в `docs/superpowers/plans/`.

## Цель и принципы (как у пользователя)

- Программа сама учится играть в оригинальный DOS-Arkanoid (Taito, 1988) в эмуляторе и проходит его.
- **Как человек:** агент видит только экран и управляет мышью; память эмулятора не читается — ни для решений,
  ни для награды, ни для конца эпизода.
- Смотреть игру вживую в любой момент; режим показа на нормальной скорости.
- Зачёт ступеней — полные игры с раунда 1, обычный запас жизней, ≥ 7 из 10 (М1: счёт ≥ 1500; М2: раунд 2; М3: раунд 5).
- **Новое требование для «чистой» версии:** механизмы игры (например, зависимость угла отскока от точки удара)
  открывает система (агент, анализ записей, большая модель), а не подсказка человека.

## Что в итоге работает (стек)

- **Эмулятор:** ядро DOSBox Pure (libretro) внутри Python через `libretro.py`, один эмулятор на процесс,
  параллельность — процессами (`SubprocVecEnv`, 10 штук на 16-ядерном ноутбуке, ~300–380 шагов обучения/с).
- **Обязательные обходы `libretro.py` и ядра:**
  - `perf=None` — perf-драйвер падает на `retro_init`;
  - клавиатура — прямой вызов `session.input.keyboard_callback`, т.к. события ядру не передаются;
  - буфер звука чистить каждый шаг, иначе память растёт;
  - кадр брать через numpy из буфера драйвера (`screenshot()` попиксельный и медленный);
  - **детерминизм:** после каждого `retro_run` вызывать `retro_get_system_av_info` (через ctypes) —
    в DOSBox Pure он ждёт конца кадра (`TCM_FINISH_FRAME`), иначе мышь применяется в момент,
    зависящий от времени хоста;
  - после `unserialize` прогнать 2 кадра, иначе `frame()` показывает картинку до загрузки;
  - отключить порты джойстиков (`set_controller_port_device(port, RETRO_DEVICE_NONE)`) — 84 → 10
    вызовов Python за кадр;
  - повторная инициализация ядра в том же процессе зависает — один эмулятор на всю жизнь процесса.
- **Игра:** `dosbox_pure_cycles = 4720` (скорость игры от циклов не зависит, `auto` невоспроизводим, `max` — 22 fps).
  Меню: Enter (EGA) → `M` (мышь) → Space; ~1480 кадров вступления до «мяч на ракетке».
  **Режим клавиатуры в этой эмуляции не двигает ракетку — только мышь.**
- **Обучение:** Stable-Baselines3 PPO, CnnPolicy, RL Zoo Atari-настройки; torch 4 потока (16 потоков отнимают ядра у сред).

## Ловушки, которые мы нашли (и как их найти раньше)

| # | Ловушка | Как проявилась | Исправление |
|---|---|---|---|
| 1 | Недетерминизм мыши в ядре | Ревью: сравнение кадров **после каждого шага**, а не только последнего | Синхронизация через `retro_get_system_av_info` |
| 2 | Бонус выхода «B» (+6710) принят за ошибку чтения | Оценка: счёт игры «застыл» | Устойчивый 3 шага скачок — новая база |
| 3 | Обучение только первой жизни | Очки по жизням в полной игре: 2500, 110, 90 | EpisodicLife: после потери жизни игра продолжается |
| 4 | Клик в момент Game Over начинал новую игру незаметно | Ревью с пробами | Падение счёта — конец игры |
| 5 | Пул учебной программы из уже проигранных позиций | Ревью | Позиция в пул — только если 60 шагов «выжила» |
| 6 | Агент «добывает» капсулы (1000 очков = как раунд) | Разбор долгой игры: 8000 из 11 630 — капсулы | Награда за очки ≤ 200/шаг, раунд +50 |
| 7 | Шум оценки по 10 играм (±2500) | Ложная «просадка» | 20 игр на двух наборах сидов |
| 8 | Трекер кирпичей 3 шага говорит «0» после сброса | Ревью | `None` до прогрева, такие снимки не брать |
| 9 | **Размытое зрение и грубое управление** | 17 млн шагов: раунд 1 не очищен ни разу | Прицельное управление + поле без уменьшения по горизонтали |
| 10 | Капсула перехватывает положение ракетки | Ревью | Ракетка по рисунку «наконечник—середина—наконечник» |
| 11 | Раунды 10+ читаются как одна цифра | Корзина «раунд 0» в пуле | Не исправлено: снять кадры раундов 10+ и разметить |

## Что сделать с первого дня в чистой версии

1. **Не уменьшать картинку** там, где важны мелкие объекты: мяч 4 пикселя, угол отскока решают ±12 пикселей.
   Начать с поля без уменьшения (или хотя бы 93×192).
2. **Точное управление сразу:** действие — целевая позиция ракетки (40 позиций + огонь), контроллер довозит
   мышь по положению ракетки на экране. «Залипание» действий 0.1, не 0.25.
3. **Детерминизм проверять покадрово**, а не по последнему кадру.
4. **EpisodicLife с первого дня** (потеря жизни — конец эпизода для обучения, игра продолжается).
5. **Награда:** очки с экрана с ограничением за шаг, раунд — главный бонус, плотный сигнал за кирпичи.
6. **Оценка:** 20 игр, отдельно — честная очистка раунда против выхода «B».
7. **Автоматический разбор неудач:** что остаётся на поле, на чём застревает агент.
8. **Открытие механизмов без подсказки человека:** по записям партий искать, какие наблюдаемые величины в момент
   касания мяча ракеткой предсказывают направление мяча после него; подтверждать вмешательством (savestate).
   Решение «дать точное зрение/управление» должно следовать из этого анализа.
9. **Датчики для награды** (счёт, жизни, кирпичи, ракетка) — по возможности выученные (маленькая сеть) или от
   большой модели со зрением, а не ручные правила.

## Идея на будущее: настоящий экран и камера

Учить в эмуляторе с «порчей» картинки под камеру (размытие, шум, перспектива, яркость), затем перенести агента
на настоящий монитор: камера + OpenCV (поиск и выпрямление экрана) + микроконтроллер-«USB-мышь»
(RP2040 / Arduino Leonardo). Учить с нуля через камеру нельзя: только реальное время, нет сохранений.
